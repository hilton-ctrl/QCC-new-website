### The repo trap

```
F:\QCC-new-website\retell-proxy\     ← vendored COPY. Editing it deploys nothing.
hilton-ctrl/qcc-retell-proxy (main)  ← what Vercel actually builds
```

Change the separate repo, push to `main`, then copy files back here to keep them
in sync. Vercel auto-deploys in ~40s. Confirm with a **side-effect-free probe**:

```
curl -s -o /dev/null -w "%{http_code}" -X OPTIONS https://qcc-retell-proxy.vercel.app/notify
# 405 = deployed   404 = not yet
```

**Never poll with POST** — every POST to `/notify` emails Michael a real lead alert.

## The Google Sheet

`https://docs.google.com/spreadsheets/d/1HKRx69Ydy5_SMbvz-oGFoBXJ09CkLwQQ5RSMR89YV4g/edit`

One row per **completed call** — widget calls, form callbacks, voicemail and
no-answer alike. Written seconds after hang-up.

**Three systems must agree and none warns you when they don't:** Retell's Post
Call Extraction field names (`name`, `mobile`, `email`, `address`, `suburb`,
`service`), the proxy's keys, and the sheet's columns. A renamed extraction
field fails silently.

- **Append-only by design.** Columns H/I/J are machine guesses the user asked
  for; nothing ever edits a row, so a correction Michael types is permanent.
- **"Called back y/n" means *this lead still needs a human to ring them***, not
  who dialled. Built the wrong way round first; corrected.
- **Column M** is the Retell call id and the de-duplication key. Hide it if you
  like — deleting it causes duplicate rows on webhook retries.
- Apps Script is a **standalone** project, so it uses `openById`, not
  `getActiveSpreadsheet()` (which returns null standalone).
- **Empty Agent Level Webhook URL** is the first thing to check if rows stop.
  That was the cause the first time.
- Retell's **voice** test fires the webhook; the text LLM playground never does,
  because it creates no call.

Full detail: `retell-proxy/google-sheets/README.md`.
